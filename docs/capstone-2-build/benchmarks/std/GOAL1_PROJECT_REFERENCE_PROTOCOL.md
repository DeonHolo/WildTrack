# Goal 1: project-defined, PDF-grounded reference protocol

**Reference method:** Researcher/project-defined technical expectations prepared with AI assistance from the synthetic STD files, the supplied STD template, the documented STD instructions and explicitly declared local gateway-mock conditions. Independent human validation is **not required** for this scoped reference and is **not claimed**. The historical `human_label_*` and `review_*` fields are retained as `PENDING` with no reviewer identity or time; they are not evidence of a missing required step under this protocol.

## Planned population and measurement unit

The fixed synthetic catalog contains 25 STD case families, 30 controlled conditions and 52 predeclared binary assertions. Each assertion has an expected boolean and specific fixture/authority rationale in `atomic-assertions.csv`; fixture SHA-256 values and scenario inputs are in `fixture-hashes.sha256`, `manifest.csv` and `goal1-condition-authority.json`. All applicable scheduled assertions, including failed/unassessable attempts, stay in the accuracy denominator. Execution coverage and per-signal confusion counts are reported separately. Missing template mapping must not be scored as if a template comparison was performed.

The two STD-19 conditions use **the same PDF bytes** with different explicit instructions and no mapped template. Deterministic PDF extraction cannot score the semantic difference between those instructions. STD-11, STD-15-non-pdf, STD-16 and STD-17-oversized include declared simulated Drive gateway behavior. A mock `Inaccessible` flag is not an observed Google Drive permission denial, and a small reference PDF plus oversized simulated metadata is not a real oversized Drive file. Only measured, applicable technical flags enter the 52-assertion component denominator; omitted semantic or provider conditions are **not** quietly counted as successes.

## Freeze and evaluation

Commit the actual fixture bytes, declared input scenarios, PDF/template hashes, project reference, exporter, scorer and application code before creating a create-only timestamped `frozen-key.json` with `freeze-goal1-reference.cjs`. The key must record exact SHA-256 values, app commit, expected assertion denominator and transparent project-defined/no-independent-review method **before** any subsequently designated evaluation output. Do not backdate the freeze or mark the earlier development probe as prospectively frozen. Execute the exporter in `OFFICIAL` mode with the key's exact SHA; do not change expected labels, code, fixture bytes or scorer between freeze and evaluation. Keep raw observations, errors and the score at distinct paths without overwriting prior results.

This test is a **source-grounded project-reference component benchmark on previously developed synthetic fixtures**, not independently validated accuracy, a blind held-out test, or a full live Google Drive / deployed-system evaluation. The original development probe already exposed the same fixture family, expected labels and checker behavior, so any subsequent run is prospective with respect to its *newly recorded output* only. The project-defined score must be interpreted accordingly; satisfying 90% against this reference does not, by itself, demonstrate the originally proposed **end-to-end** Goal 1 target. Actual provider-backed checks or an explicitly amended, academically accepted component-level objective are separate from waiving a reviewer.
