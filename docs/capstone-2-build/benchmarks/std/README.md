# WildTrack STD checker benchmark

This folder contains synthetic controlled fixtures for the WildTrack Document Check and AI Review technical benchmark. It is not participant data and it does not prove that real software testing occurred.

## Evaluation authority

The authoritative source remains the owner-supplied private file `docs/STD TEMPLATE.pdf` plus `docs/WildTrack_Document_Validation_Test_Plan.md`.

The source template was inspected with PDFBox on 2026-09-19:

- seven pages;
- body structure: Introduction, Test Plan, Test Cases, Appendix/Test Logs;
- body-page headers still contain `SchedEase`;
- `Testing Tools and Environment` is numbered `3.3` inside the Test Plan chapter;
- the Table of Contents repeats section names that must not count as proof that the corresponding body section exists.

These quirks are preserved as benchmark authority facts. WildTrack must not require `SchedEase`, and it must not turn the numbering typo into a project requirement.

## Automated Goal 1 scoring

`atomic-assertions.csv` now defines **52 draft expected classifications** spanning all 30 manifest conditions and 25 required STD families, including separate corrupt/non-PDF STD-15 cases, password/oversize STD-17 cases, the shared-PDF STD-19 instructions pair and both STD-25 incident variants. Every row still requires independent source inspection, and every expected label remains `PENDING`; these are not achieved results. Technically readable PDFs with irrelevant text or fictional execution claims are not automatically invalid PDF files. Deterministic scoring deliberately excludes semantic testing-completeness judgments from the accuracy denominator.

Run the small Node regression suite from the repository root:

```powershell
node --test docs/capstone-2-build/benchmarks/std/score-benchmark.test.cjs
```

`StdBenchmarkObservationExportTest` invokes the actual backend `PdfInspector` and `TemplateComparator` for physical PDF classifications and real `FileCheckService` with an **explicitly mocked gateway** for the filename, MIME, inaccessible and oversized-metadata conditions. It performs **no real Google Drive requests**. Small local reference files for STD-16 and STD-17-oversized are not themselves restricted or greater than the configured file-size limit, and the simulated gateway `Inaccessible` result is not proof of a real Drive HTTP 403. An ordinary test run skips the exporter. Explicit export requires a matching 40-character Git HEAD and clean committed production Document Check sources, validates the full case catalog and source hashes, and refuses overwriting past observations. A probe run **before actual independent label review** is a versioned engineering/development probe only. Freeze a fully reviewed key and perform a separately named subsequent run for formal measurement.

```powershell
Push-Location backend
$benchmarkRevision = (git rev-parse HEAD).Trim()
mvn -q "-Dtest=StdBenchmarkObservationExportTest" "-Dbenchmark.app.commit=$benchmarkRevision" "-Dbenchmark.observations.output=../docs/capstone-2-build/benchmarks/std/probe-$benchmarkRevision.csv" test
Pop-Location
node docs/capstone-2-build/benchmarks/std/score-deterministic.cjs --observations "docs/capstone-2-build/benchmarks/std/probe-$benchmarkRevision.csv" --output "docs/capstone-2-build/benchmarks/std/probe-$benchmarkRevision-score.json"
```

The exporter records per-fixture SHA-256, template SHA-256, HEAD SHA, UTC timestamp, classification/error and clean production-checker status. The scorer verifies fixture/template hashes, rejects duplicate fixture IDs and incorrect provenance, keeps every scheduled assertion in the accuracy denominator when an observation fails or is absent, and groups confusion matrices by the meaning of each binary indicator. It reports `null` when precision, recall, false-positive rate or false-negative rate has a zero denominator. Inspect the per-assertion outcomes and errors rather than reporting one synthetic subset score as general Document Check performance.

`PROVISIONAL_NOT_OBJECTIVE_1_RESULT` is a hard research gate: the 25 families, required variants, all applicable reviewed assertions and independent labels **dated before** a separate scored observation are required. Follow `GOAL1_INDEPENDENT_REVIEW_PROTOCOL.md` to have an actual teammate inspect the PDFs and authority without looking at checker outcomes; record real reviewer names/timestamps in both manifest and atomic assertions. Then create the immutable Goal 1 lock with `freeze-goal1-reference.cjs --output <NEW frozen-key.json> --review-attestation <actual-review-record>` before collecting scored observations. Pass that key to `score-deterministic.cjs --freeze <frozen-key.json>`; the scorer verifies answer-key, fixture, conditions, template, source and scorer hashes and review/freeze chronology. It never accepts a fictional reviewer. **A locally mocked gateway does not establish full live end-to-end Document Check accuracy**, even if the offline score meets 90%; actual provider/Drive-path evidence and academic approval remain separately needed where required.

## Automated Goal 2 scoring

**Runner scope:** the opt-in provider benchmark invokes `GeminiAiReviewProvider.review` using `AiReviewService.SYSTEM_INSTRUCTION` and the app model/format. It does **not** run the full Admin/Drive/cache/UI pathway or the private `AiReviewService.groundAndValidate` post-filter. All Goal 2 findings are limited to this provider-backed component on synthetic STD inputs and must not be called deployed end-to-end AI Review accuracy.

`ai-checklist.csv` contains eleven project-defined binary issue/clean decisions across ten planned **synthetic STD** fixtures. Goal 2 uses a **project/researcher-defined, PDF-grounded reference checklist** prepared through AI-assisted review of the ten actual extracted PDF source texts and supplied authority, with source excerpts and rationales for every decision. The CSV's `reference_method=PROJECT_AI_ASSISTED_PDF_AND_AUTHORITY_REVIEW` and `reference_status=FROZEN_PROJECT_DEFINED` describe project-defined reference preparation, **not** manual user review or independent human validation. The actual pre-run `frozen_at`, app commit and source/instructions/protocol hashes for the completed 2026-09-21 pilot are preserved in `results/goal2-20260921/frozen-key.json`; do not claim the source was independently verified. Goal 1 manifest `human_label_review` fields remain separately `PENDING`. See `GOAL2_REFERENCE_CHECKLIST.md` and `AI_PILOT_PLAN.md`.

The evaluator `score-ai.cjs` does **not** invoke Gemini, supply missing source evidence, or manufacture reviewer judgments. It enforces the project-defined reference without treating Goal 1's independent-review fields as Goal 2 evidence, validates frozen fixture/answer-key/instructions/protocol hashes and timestamps, checks on-disk raw-report hashes and scores only fresh reports with documented cache status `MISS`. A complete per-report source audit is required before interpreting its agreement or traceability rates. The portable actual nine-success/one-HTTP-503 record and complete AI-assisted audits are in `results/goal2-20260921/`.

```powershell
node docs/capstone-2-build/benchmarks/std/score-ai.cjs --record docs/capstone-2-build/benchmarks/std/ai-run-record.template.json
```

The planning-template command still represents ten `not_attempted` outcomes and null agreement/traceability; **it is not a substitute for the actual run above**. The actual reference was source-backed with AI assistance and frozen by `freeze-ai-reference.cjs` before the first official provider call. The earlier out-of-pilot STD-24 development smoke is excluded; no independently human-verified answer key is claimed. Do not mark Goal 1 independent-review fields `VERIFIED` on the strength of this Goal 2 reference.

The opt-in `StdAiPilotRunTest` records a durable attempt claim **before** its one allowed call on each whitelisted fixture, never automatically retries or invokes a paid fallback, and preserves actual `fresh_success`, `cache_hit`, `quota_failure`, `provider_failure`, `transport_failure`, `invalid_response` or `outcome_unknown` with `attempted_at`, fixture/template/app hashes and a precise reason. Nonfresh outcomes remain in the fixed ten-attempt coverage denominator and have no fabricated content score. Fresh reports retain `cache_status: "MISS"`, provider/model/prompt, the parsed report and the separate raw Gemini HTTP response with actual SHA-256 and `responseId` where available. A request-ID header was not returned; its null value is not substituted with the response ID.

For each fresh report, `decisions` contains one `observed: "present"|"absent"|"unassessable"` entry per frozen criterion, with `audit_method: PROJECT_SOURCE_AUDIT`, raw-report pointer and explanatory notes. Every distinct substantive report claim is inventoried with its exact report text/pointer, `source_kind: "pdf"|"official_template"|"deliverable_instructions"|"unsupported"|"unassessable"`, exact supplied PDF/authority excerpt where supported, explicit `traceable: true|false|null`, and project/AI-assisted audit notes. The completeness attestation references the exact raw structured report SHA-256 and accounts for summary/action assertions. No fictional independent reviewer identity is supplied. A claimed absent mandatory-template requirement is unsupported if the applicable input authority does not require it; STD-18 has no mapped official template.

The aligned scorer preserves the fixed ten-attempt denominator, separately reports failed outcomes and unassessable decisions, and includes **all substantive claims, even unassessable ones, in the conservative traceability denominator**. A zero-claim report has null, not 100%, traceability. The actual run produced **9/10 fresh reports, 7/10 (70%) project-reference agreement, and 24/43 (55.8%) source-supported claims**; neither proposed threshold (85% agreement or 90% traceability) was achieved. These are ten controlled STD conditions, not proven independent accuracy on student submissions.

Because Goal 1 expanded the living manifest and hash list **after** the original Goal 2 provider run, its first-pilot references have been byte-for-byte recovered from the original pre-run Git commit into `archives/goal2-20260921/`. Every archived byte is checked against the original frozen-key SHA-256. Reproduce the unchanged historical score against those original references, not the expanded current Goal 1 catalog, without credentials or Gemini calls:

```powershell
node docs/capstone-2-build/benchmarks/std/score-ai.cjs --record docs/capstone-2-build/benchmarks/std/results/goal2-20260921/ai-run-record.json --source-snapshot docs/capstone-2-build/benchmarks/std/archives/goal2-20260921
```

## Scoring boundary

- Deterministic Document Check observations can be run locally and recorded with exact denominators.
- AI Review results require a fresh provider call to count as fresh. Cached results do not count as fresh pilot runs.
- No paid fallback or automatic repeated provider calls are authorized by this benchmark.
- Goal 1 still requires independently verified human expected labels for its research score. Goal 2 uses a documented researcher-defined PDF-grounded reference, not a mandatory independent reviewer; do not claim independent verification unless it actually occurred.
- Results are scoped to synthetic STD fixtures and must not be generalized to all academic documents.
