# WildTrack STD checker benchmark

This folder contains synthetic controlled fixtures for the WildTrack Document Check and AI Review technical benchmark. It is not participant data and it does not prove that real software testing occurred.

## Evaluation authority

The authoritative source remains the owner-supplied private file `docs/STD TEMPLATE.pdf` plus `docs/WildTrack_Document_Validation_Test_Plan.md`.

The source template was inspected with PDFBox on 2026-09-19:

- seven pages;
- body structure: Introduction, Test Plan, Test Cases, Appendix/Test Logs;
- body-page headers still contain `SchedEase`;
- `Testing Tools and Environment` is numbered `3.3` inside the Test Plan chapter;
- the Table of Contents repeats section names that must not count as proof that the corresponding body section exists.

These quirks are preserved as benchmark authority facts. WildTrack must not require `SchedEase`, and it must not turn the numbering typo into a project requirement.

## Fixtures

`manifest.csv` is the frozen answer-key draft. The independent human label-review column intentionally remains `PENDING` until a teammate reviews the expected labels before examining WildTrack output.

`STD-01` is the exact supplied template itself and is referenced in the manifest rather than copied into this tracked folder. The other PDFs are synthetic fixtures generated by `generate-fixtures.cjs`.

Generate the synthetic PDFs from the repository root:

```powershell
$env:NODE_PATH=(Resolve-Path 'frontend/node_modules').Path
node docs/capstone-2-build/benchmarks/std/generate-fixtures.cjs
```

The generator writes only the benchmark fixture directory. It never edits the supplied template.

Run the deterministic fixture regression from `backend` when the owner-supplied template is present:

```powershell
mvn -q "-Dtest=TemplateComparatorTest,StdBenchmarkFixtureTest" test
```

`deterministic-observations.csv` preserves the 2026-09-19 local probe output. It is an observation record, not an independently reviewed benchmark pass rate.

## Automated Goal 1 scoring

`atomic-assertions.csv` defines 16 provisional atomic expectations over the 11 prepared PDFs, including eleven readability assertions, three template-like indicators and two Test Approach body-heading omissions. It deliberately excludes semantic content/filler judgments from deterministic scoring. Add the remaining fourteen case families and all required split/paired variants before evaluating the proposed Goal 1 threshold over the full planned set. The script explicitly checks the separate corrupt/non-PDF STD-15 cases, password/oversize STD-17 cases, both STD-19 requirement conditions and paired STD-25 outcomes. Add rows for every applicable technical assertion before the evaluation run, including applicable failure and access cases. Freeze the completed answer key before collecting the scoring observations.

Run the small Node regression suite from the repository root:

```powershell
node --test docs/capstone-2-build/benchmarks/std/score-benchmark.test.cjs
```

`StdBenchmarkObservationExportTest` invokes the actual backend `PdfInspector` and `TemplateComparator`. An ordinary test run skips export. An explicit export requires a matching 40-character Git HEAD and no tracked changes in production Document Check files. It refuses to replace an existing observation file. **The development checkout currently has uncommitted checker changes**, so run the exporter only after those changes are reviewed and committed to the feature branch. With the checker files committed, run this from the repository root, choosing a new filename for each run:

```powershell
Push-Location backend
$benchmarkRevision = (git rev-parse HEAD).Trim()
mvn -q "-Dtest=StdBenchmarkObservationExportTest" "-Dbenchmark.app.commit=$benchmarkRevision" "-Dbenchmark.observations.output=../docs/capstone-2-build/benchmarks/std/probe-$benchmarkRevision.csv" test
Pop-Location
node docs/capstone-2-build/benchmarks/std/score-deterministic.cjs --observations "docs/capstone-2-build/benchmarks/std/probe-$benchmarkRevision.csv" --output "docs/capstone-2-build/benchmarks/std/probe-$benchmarkRevision-score.json"
```

The exporter records per-fixture SHA-256, template SHA-256, HEAD SHA, UTC timestamp, classification/error and clean production-checker status. The scorer verifies fixture/template hashes, rejects duplicate fixture IDs and incorrect provenance, keeps every scheduled assertion in the accuracy denominator when an observation fails or is absent, and groups confusion matrices by the meaning of each binary indicator. It reports `null` when precision, recall, false-positive rate or false-negative rate has a zero denominator. Inspect the per-assertion outcomes and errors rather than reporting one synthetic subset score as general Document Check performance.

`PROVISIONAL_NOT_OBJECTIVE_1_RESULT` is a hard research gate: all 25 case families, required variants, complete frozen atomic assertions and independently verified labels **dated before** the scoring observations must be present before treating output as a research score. An independent teammate must inspect the PDF and authority without looking at the checker outcome, then set `human_label_review=VERIFIED`, `human_label_reviewer`, `human_label_reviewed_at` on its manifest row and `review_status=VERIFIED`, `reviewer`, `reviewed_at` for each atomic assertion. Preserve the earlier pending/review history and version the key if correcting an expectation after observation. The generated score is still scoped to these synthetic STD fixtures.

## Automated Goal 2 scoring

**Runner scope:** the opt-in provider benchmark invokes `GeminiAiReviewProvider.review` using `AiReviewService.SYSTEM_INSTRUCTION` and the app model/format. It does **not** run the full Admin/Drive/cache/UI pathway or the private `AiReviewService.groundAndValidate` post-filter. All Goal 2 findings are limited to this provider-backed component on synthetic STD inputs and must not be called deployed end-to-end AI Review accuracy.

`ai-checklist.csv` contains eleven project-defined binary issue/clean decisions across ten planned **synthetic STD** fixtures. Goal 2 uses a **project/researcher-defined, PDF-grounded reference checklist** prepared through AI-assisted review of all ten actual extracted PDF source texts and applicable supplied authority, with source excerpts and rationales recorded for each decision. The CSV's `reference_method=PROJECT_AI_ASSISTED_PDF_AND_AUTHORITY_REVIEW` and `reference_status=FROZEN_PROJECT_DEFINED` describe that **prepared project-defined reference**, **not** manual user review, completed independent human validation, or a dated run-level freeze record. The run-level `frozen_at` and complete key/fixture/instructions/protocol hashes must be recorded **before** official provider observations; they are not claimed as completed here. Reference agreement must not be called independently established AI accuracy. Goal 1 manifest `human_label_review` fields remain separately `PENDING` until genuine independent review. See `GOAL2_REFERENCE_CHECKLIST.md` and `AI_PILOT_PLAN.md`.

The evaluator `score-ai.cjs` does **not** invoke Gemini, fill in source evidence, or manufacture reviewer judgments. To produce a valid Goal 2 research score, its run-record and gate must explicitly accept the researcher-defined reference **without** treating Goal 1's independent-review fields as Goal 2 evidence. It should verify source-grounded checklist status, the frozen fixture/answer-key/instructions/protocol hashes and timestamps, and on-disk raw-report hashes, scoring only fresh reports with documented cache status `MISS`. Do not bypass a failing gate by inventing an independent reviewer. Confirm actual scorer/schema compatibility before reporting an automated result.

```powershell
node docs/capstone-2-build/benchmarks/std/score-ai.cjs --record docs/capstone-2-build/benchmarks/std/ai-run-record.template.json
```

The planning-template command represents ten `not_attempted` outcomes, fresh-run coverage `0/10`, and `null` checklist-agreement and claim-traceability rates. **It is not evidence of an attempted provider run.** The project-defined checklist already records AI-assisted actual-PDF-text source excerpts/rationales; do not reinterpret these as a manual user audit or independently verified ground truth. Before a real pilot, preserve this prepared reference with exact checklist/manifest/template/fixture hashes, `instructions_sha256`, `protocol_sha256`, app commit/model/prompt version and real run-level `frozen_at` **before observing official provider results**. If development/smoke output was previously seen, disclose it rather than claiming a fully blinded process. Independent human review may be separately documented if it actually occurs, but is not mandatory for Goal 2; do not mark Goal 1 independent-review fields `VERIFIED` on the strength of this reference.

For an actual attempt, copy the planning template to a new run record and replace its fixture outcome with `fresh_success`, `cache_hit`, `quota_failure`, `provider_failure`, `transport_failure` or `invalid_response`, preserving each planned fixture ID. Attempt each fixture **once, free-tier only**, with no automatic/manual retry to improve its score or paid fallback. Record `attempted_at`, `fixture_sha256`, `template_sha256` and `app_commit` for each attempt. Nonfresh outcomes need an explicit `reason` and never enter content denominators, but remain in the fixed ten-attempt coverage tally. For fresh success record `cache_status: "MISS"`, `provider`, `model`, `provider_request_id`, `prompt_version`, `report_path` and `report_sha256`; save the entire raw provider report at that path relative to the run record. Preserve genuine request and cache evidence so freshness can be checked.

For each fresh report, the **researcher** fills `decisions` with one entry per frozen `decision_id`: `observed: "present"|"absent"|"unassessable"`, actual reviewer identity/type and ISO review time, `evidence_reference` pointing to the raw report and explanatory `notes`. Inventory and source-audit **every** substantive report claim separately, preserving `claim_id`, its report text/pointer, `source_kind: "pdf"|"official_template"|"deliverable_instructions"|"unsupported"`, source passage/location where supported, explicit supported/unsupported/uncertain judgment, rationale and real reviewer identity/type/time. The legacy record uses `traceable` boolean and `reviewer_id`/`reviewed_at`; until schema alignment, an uncertain claim must be documented explicitly and **must not** be counted as supported. Record the full-claim-inventory check against the raw-report SHA-256 only after auditing the entire report. A claim inventing an absent mandatory-template requirement is unsupported even if a model asserts it confidently. In STD-18 no official template is mapped, so it cannot authorize a claimed mandatory template requirement.

The aligned AI scorer must preserve the fixed attempt denominator of ten, report nonfresh/failed attempts by outcome, exclude unassessable decisions from the adjudicable-decision denominator while reporting their counts/reasons, and use `null` when no substantive claims exist. Zero claims must not be described as 100% traceable. An automated score cannot independently establish natural-language source support; researcher adjudication with per-claim report/source evidence and explicit uncertainty is required. Report both planned thresholds (85% checklist agreement, 90% traceability) only with actual fresh-run numerators, denominators and caveats. Even a target-meeting pilot remains researcher-referenced evidence about these ten synthetic STD conditions, not proven accuracy on student submissions.

## Scoring boundary

- Deterministic Document Check observations can be run locally and recorded with exact denominators.
- AI Review results require a fresh provider call to count as fresh. Cached results do not count as fresh pilot runs.
- No paid fallback or automatic repeated provider calls are authorized by this benchmark.
- Goal 1 still requires independently verified human expected labels for its research score. Goal 2 uses a documented researcher-defined PDF-grounded reference, not a mandatory independent reviewer; do not claim independent verification unless it actually occurred.
- Results are scoped to synthetic STD fixtures and must not be generalized to all academic documents.
