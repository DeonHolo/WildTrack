# Goal 2: separate v6 production-filtered AI Review follow-up

**Status:** prospective synthetic technical follow-up after the already-published ten-STD raw-provider v3 pilot and six-SRS v4 provider pilot. Those historical outcomes, attempts, errors, answer keys and reports remain untouched. This new ten-case cohort is NOT the original Goal 2 pilot population, is NOT an independent blinded holdout, and cannot retroactively turn a failed historical target into a passed result. Record any results with its exact app/prompt/model, study population and qualifiers.

## Reference, scope and denominators

- Project/researcher-defined expected issue/clean decisions are established with AI assistance from each **newly generated fictional synthetic STD PDF**, applicable instructions and mapped **new safe synthetic STD template**, with exact source excerpts and rationales in `REFERENCE.json` and `manifest.json`. Independent human adjudication is neither mandatory nor claimed. When an authority is missing, do not invent a mandatory named heading. A template's outline alone does not prove a heading is universally mandatory; its missing body section can support a structural advisory. A TOC mention is not a body section. An intentionally synthetic label does not make a correctly typed STD the wrong deliverable.
- The planned cohort has exactly ten prescribed distinct-case IDs `G2-01` through `G2-10`. Both clean and faulty controls are scheduled, including source-backed omissions, TOC-only headings, existing but placeholder bodies, an optional section, example project identity, obvious wrong-document content, a document-embedded bogus requirement, and no-mapped-template cases with generic versus explicit supplied instructions. Controlled fictional prose never claims that actual software was run or that students submitted these files. See the manifest for the exact decisions. Conditions testing different authority contexts must send the correct authority to the provider and production postprocessor.
- At most **one new actual Gemini `generateContent` request per prescribed case**, with durable exclusive `attempt-started.json` claim written before the request; never remove a claim and retry an unknown/HTTP 503/429 outcome for a better score. No automatic paid fallback. Freeze the exact manifest, reference decisions, source PDF/template/instruction hashes, scorer, one-shot runner, production app commit, model, prompt/cache versions and this protocol **before the first live request**. Each attempt records HTTP status and fresh/cache evidence, raw provider bytes, raw structured response and the **same final production `AiReviewService.groundAndValidate` postprocessing method** used by WildTrack. Raw Gemini claims do not stand in for final WildTrack output. No original private/student SRS, official private PDFs, API key or untracked secret may enter these fixtures or committed result files.
- Fresh provider coverage: fresh successful production-filtered reports divided by **10 prescribed attempts**. Checklist agreement: number of frozen, adjudicable issue/clean decisions matching actual final output divided by all such decisions in fresh successful final reports, with failed and unassessable cases separately reported, not silently removed from coverage. Traceability: **all distinct substantive final-report claims** (findings, missing-section/requirement assertions, and extra factual/obligation claims introduced by summary or suggested action) are inventoried and individually grounded to the exact source PDF passage or explicitly supplied template/instruction requirement. Count `SOURCE_SUPPORTED` only when the cited passage truly supports the claimed meaning, not merely because a quotation occurs verbatim in the source. Unsupported and unassessable claims both remain in the substantive-claim denominator; generic app limitations and duplicate paraphrases of an already-inventoried claim are not new substantive claims. Require a retained, source-quoted project-defined audit of **every** distinct claim before computing a traceability numerator; no automated quote match, unsupported source inference, fabricated reviewer or fictional audit approval.
- Targets of **85% checklist agreement** and **90% source-supported substantive claims** are the previously proposed Goal 2 descriptive pilot gates. Treat zero denominators as non-estimable. Report the scheduled denominator, negative/positive decision counts, case-level false alarms/misses, uncertainty, fresh-run coverage and HTTP errors. This run measures actual provider plus production report postprocessing on synthetic files, **not** the deployed form, live Drive authorization/cache/UI, actual student work, completed software testing, or independent population-wide model accuracy.

## Evidence chronology and interpretation

Source references and expected labels may be revised **before** the freeze, recording the reason; after observing any provider output, preserve the original key and record any improvements in a separately versioned experiment. Preserve one-shot failures even when a later paid or manual retry would be possible. A new performance percentage from this separately frozen cohort is an exploratory source-grounded synthetic follow-up, not replacement of the initial historical STD 7/10 checklist agreement, 24/43 traceability, or one HTTP 503, and not proof that a goal for a different cohort or production end-to-end environment passed.
