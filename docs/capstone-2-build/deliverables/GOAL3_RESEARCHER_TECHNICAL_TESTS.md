# Goal 3: separate researcher-controlled technical checks

**Working protocol, 2026-09-22.** The owner removed the research-only `Validation Step` question from the live WildTrack Refactored SRS form after the original mandatory T1/T2 research method was superseded. The question is no longer a prerequisite or an editing target. Historical versions and any saved old values remain historical evidence. A deterministic **local mocked-Drive** test run has now been executed and separately reported in `GOAL3_RESEARCHER_LOCAL_RUN_20260922.md`. Its local PASS results do not establish real Google Drive provider or deployed browser behavior; the full external-provider stage described below has **not** been executed. This protocol concerns actual application behavior, not the Google Form questionnaire or its response tab.

## Scope and safety

Run only with an authorized researcher/test account, a synthetic student record in an isolated non-grading workspace, and fictional files under researcher control. Never choose a real student's identity, change their submission, reaccept/revoke a deliverable, or upload fictional content to the actual course validation cohort. Freeze the actual tested build/revision, environment, workspace, form configuration, date/time and relevant Document Check policy before the first run. Confirm that the test form has **required PDF Drive Link**, without `Validation Step`. If the test environment does not reflect the deployed configuration, disclose that difference instead of calling it a live validation.

Record each scenario's starting response ID/revision, submitted field values, API or UI outcome, final persisted state, applicable Document Check report/status, source timestamps and anonymized evidence reference. Keep synthetic Google Drive links and any credentials outside publicly committed documents. Put only pseudonymous run IDs and non-sensitive aggregate outcomes in the final report. A passing local mocked/component test is not evidence that these end-to-end scenarios ran against the actual deployed WildTrack/Drive integration.

| Run | Researcher action and expected observation | Proof to retain |
|---|---|---|
| R3-01, missing required PDF | With required academic identity bound to the synthetic student, leave the PDF link blank and attempt **Submit response**. Verify same response ID, the persisted new PDF link, preserved synthetic student/workspace/deliverable association, a genuine revision/history event and correct initial-versus-edited timestamps. Note that a no-op save must not fabricate an extra revision. The edit is of the **PDF link**, not the removed `Validation Step`. | Before/after response IDs, original/current field values, history version IDs and timestamps, and any expected scoped Document Check invalidation/recheck for the changed PDF. |

An additional no-op save after R3-03 is useful for confirming that unchanged values do not create a fictitious edit or alter lateness. If time is limited, keep it explicitly optional and report whether it was executed.

## Result recording

Use one restricted row per run: `run_id | build/environment | observed_at | expected_stage | actual_stage | initial_response_id | resulting_response_id | initial_revision | resulting_revision | check_status | outcome(PASS/FAIL/UNVERIFIED/NOT_RUN) | evidence_reference | deviation_or_limitation`. A PASS requires the **actual** reported observations and evidence; code inspection alone is not a PASS. Report failed or inaccessible runs without silently retrying away the first failure. Do not mix these three researcher runs with `N_INITIAL`, `C_INITIAL`, student participant counts, or the historical Admin T1/T2 `overallPass`.

The real student's revised Goal 3 assessment remains a separate, appropriately consented and evidence-backed **initial saved-record** study, subject to the amendment and adviser review. Removing the visible `Validation Step` does not delete the old research chronology or retrospectively prove that any student actually edited a response.
