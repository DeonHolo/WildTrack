# Deadline-aware Drive PDF monitoring, September 22, 2026

**State: implemented and tested locally; OFF by default, NOT deployed.** The monitor operates only on the explicitly selected active academic workspace's saved, unarchived PDF artifact links. It neither changes the published Google Form nor makes students wait through extra submission-time verification. No permanent PDFs are stored, which respects the hosting storage limit. Monitoring is engineering evidence and does not count toward student Goal 3 scores.

## Operation

The opt-in worker recalculates eligible unique Drive file IDs from saved form responses once per minute. It derives each file's monitoring priority from its associated deliverable deadlines in Asia/Manila. An initial observation uses earlier actual Document Check metadata when available. Without a prior observed checksum, a first metadata read does not reconstruct what was present at submission time.

Normally a file receives one metadata-only request per hour. From 24 hours before until 48 hours after the deadline, the interval is five minutes. The default cap of 20 unique metadata checks per minute spreads an initial set of 60 shared PDFs over approximately three cycles, subject to provider delays. Moving a deadline nearer recalculates the priority on the next minute tick. A finalized archived response version stops being monitored; a subsequently saved version remains eligible.

Unchanged checksums require no PDF download or parse. A verified new checksum, even a small modification, triggers one shared file download and PDF parse for all associated responses. Each individual response retains its own field-scoped Document Check report, original saved timestamps and distinct template/academic context. Previous reports are preserved. The manual Recheck all documents and Check all unchecked actions also batch by canonical file ID before progressive chunking, avoiding repeated downloads when five team members submit the same shared PDF.

Monitoring events distinguish CONTENT_CHANGED, ACCESS_UNAVAILABLE, DOWNLOAD_UNAVAILABLE, FILE_TYPE_CHANGED, CHANGE_AWAITING_CHECK and informational METADATA_CHANGED or ACCESS_RESTORED. Today’s Work presents one prominent unresolved significant event per file with an affected-submissions count. Personal Open/Dismissed tabs retain staff dismissals without deleting history, and a genuinely newer significant event can surface after an older one was dismissed. No academic acceptance or grade changes automatically.

An unexpected provider metadata file ID is rejected rather than being recorded under a different submitted link. When the provider has no comparable MD5 checksum but reports a newer modification time, WildTrack re-downloads/rechecks the current PDF once and records an explicitly **unverified** change observation. That metadata timestamp alone is not represented as proof of different PDF bytes. A temporary provider failure preserves the last known accessibility observation instead of manufacturing an access-restoration alert. Staff event visibility is mapped only through actual active submitted PDF fields in the staff member's authorized teams, never through an arbitrary free-text field containing a Drive URL. An acknowledged newer significant event does not conceal an earlier undismissed significant event for the same file.

## Controlled enablement

The operator must set WILDTRACK_FILE_MONITOR_ENABLED=true and WILDTRACK_FILE_MONITOR_WORKSPACE_ID to the exact active workspace UUID after controlled real-Drive access tests and owner review. WILDTRACK_FILE_MONITOR_MAX_FILES_PER_CYCLE defaults to 20 and WILDTRACK_FILE_MONITOR_TICK_MS to 60000. The existing configured Drive API key must be able to read the submitted files. No new OAuth scopes or mandatory student loading screen are introduced.

## Evidence boundaries

Local automated tests used 300 fictional response records sharing 60 file IDs, five synthetic students sharing one generated PDF with mocked provider metadata/downloads, and staff-authorization checks. They do NOT verify deployed browser behavior, live Google Drive file access, or real student submissions. A five-minute interval is a scheduling target, not a guarantee under provider outages or backlog. Same-link replace-and-restore between observations can escape detection; checksum changes prove different bytes, not intent, materiality or exact contents at the deadline. Metadata-only modifications do not prove a PDF content edit. Native Google Docs/Sheets/Forms have different metadata and are not treated as uploaded binary PDF files. The monitor preserves small metadata and reports only, not immutable PDF snapshots.
