# Goal 3 protocol amendment — 2026-09-22 (working, not adviser-endorsed)

## Why this is changing

The original prospective Goal 3 protocol required each participating student to deliberately submit an incomplete Refactored SRS response, successfully submit a valid PDF link (T1), then edit the **same** response and change only `Validation step` to `Revised submission` (T2). The distributed questionnaire and its connected spreadsheet, plus the temporarily implemented WildTrack Admin `Validation Study` view, were prepared around that protocol.

After participant collection had started, the owner observed that many students naturally submit only once and have no reason to edit their documents. Treating a genuine, valid initial submission as a failed revision therefore tests whether students followed an artificial study script, not whether WildTrack saved the submission correctly. The owner chose to simplify Goal 3 and keep revision/missing-link/wrong-file-type tests as **separate researcher-controlled technical checks**. This is an explicit **post-distribution protocol amendment**; do not rewrite the original task logs, old study results, frozen Goal 1/2 experiments or the questionnaire answers already received.

## Revised objective and exact scope

**SMART Objective 3 (proposed revised scope).** By the close of the MVP validation period, verify that at least 95% of **eligible, consenting students' assessable initial saved Refactored SRS submission records** in the validation workspace preserve the correct canonical student association, workspace, deliverable, required PDF link and saved field values, with a real original saved response identity/state. The assessment uses real persisted response/system evidence and separately corroborated researcher observations where available. The unit is **one verified initial saved response per eligible student**, not an artificially scheduled edit and not a Google Form answer.

- **Numerator C_INITIAL:** eligible initial saved response records for which *every applicable required persistence/association assertion* is supported by actual system evidence and passes.
- **Denominator N_INITIAL:** all eligible **initial saved response records selected under an explicit, dated inclusion rule**, including a selected record with a failed or unverified required assertion. Do not silently remove hard cases or change the inclusion rule after seeing results. If no qualifying records exist, the rate is **not estimable**, not 100%.
- **Primary metric:** `INITIAL_SAVED_CORRECTNESS = C_INITIAL / N_INITIAL`; proposed working threshold `>=95%`. Record individual assertion failures and `UNVERIFIED` separately. A selected row with missing independent corroboration is **not a PASS**; the final report must distinguish failures from unassessable evidence.
- **Generalization limit:** this is **correctness among observed initial *saved* records**, **not** a success rate across *all attempted* transactions. Errors before persistence, abandoned forms, rejected invalid links and sessions with no saved record are outside this primary denominator unless independently logged. Never call this end-to-end attempt success, claim that all students succeeded, or use an auto-generated saved-response list as proof of a failed-attempt rate.
- **Student identity consent:** the existing Form's consent text specifically references questionnaire data and, where applicable, **controlled task evidence**. Do not assume that ordinary submissions made outside the controlled task are automatically authorized for research simply because the student submitted a PDF or completed the questionnaire. Record an affirmative basis permitting analysis of each chosen student/system record under the revised natural-submission scope, or exclude that record until consent/academic approval is clarified. A one-person consultation and questionnaire response rows are not substitutes for this permission.
- **Historical records:** mark which candidate submissions were already seen on the earlier Admin Validation Study view and which were selected after this amendment. If a genuine initial version is unavailable (e.g. `Revised submission`, revision 1, zero recorded history), do **not** reconstruct it from the current `Validation step` choice or award a pass. Record the case as `UNVERIFIED` or outside the justified initial-record cohort with its reason.

### Required initial-saved-record checks

For each eligible record, confirm with appropriate original persisted version/system evidence these **five primary checks**: (1) student association matched the intended authorized student under the actual account/student binding, (2) workspace was the active Semester 1 validation workspace, (3) deliverable was Refactored SRS, (4) the actual initial saved record/response ID and original version exist, and (5) a required Drive PDF link and applicable field values are present and internally consistent in that original saved record. Distinguish evidence of **values actually stored** from separate proof that they exactly match pre-save typed input (which may be unavailable). Record student-visible readback **as a separate supporting check only when actually observed**; lack of an old screenshot must not silently convert a technically verified persisted record into a failure. When a *primary* check is unobservable, label it `UNVERIFIED`; a `Revised submission` label alone does not prove an earlier edit or T2. A linked PDF's content cannot be inferred from its name or URL suffix alone.

Do not silently use the old temporary Validation Study `Overall pass` field: it requires T1+T2 and says nothing about the new initial-only score. Existing data are descriptive until the page/export implements a separate **initial-saved record** analysis with appropriate evidence and provenance; do not simply rename the old `Overall pass` column to `Goal 3 pass`.

## Separate technical checks, not additional student participants

Researcher-controlled, fictional/synthetic, permitted-account tests may check (a) required blank PDF link is rejected, (b) a non-PDF/DOCX link is handled according to actual pre-save validation versus async Document Check policy, and (c) an edit preserves response identity, untouched fields and actual revision state. Report test account, date, version and the actual expected behavior. These checks are supporting engineering evidence; they do **not** increase the student denominator, prove a natural student revision occurred, or count as extra participants.

## Existing distributed Google Form: keep collecting

The existing current-status clarity 1–5 and **“After submitting or editing a response”** 1–5 question apply to students who **submitted OR edited**, so no task revision is required to answer them. The optional `Editing a saved response` and `Adviser feedback` improvement checkboxes are only applicable **if a student actually used/saw the feature**; staff must first have provided feedback for the latter to appear. Unselected options mean only “not selected”, **not** an endorsement of an inaccessible feature. Keep ratings/descriptive feedback outside the Goal 3 correctness numerator/denominator.

The original Google Form source describes an *optional* controlled task and has an experience-basis choice for students who used the workflow **outside** that task. The owner additionally showed a spreadsheet column beginning `For this evaluation...` whose full live wording/choices are not captured in the repository or the three later screenshots. Do not infer that a response saying “Completed both...” proves two persisted tasks. Review that **one live question** before deciding whether to retire or reword it prospectively; no wholesale Form rebuild or changing already-submitted responses is needed. If any published description/consent text changes, record the effective date and keep both instrument versions distinct. In particular, do not broaden research consent retroactively.

## Existing connected Sheet migration

The owner explicitly requested **replacement** of the existing `Objective 3 Task Log` and `Objective 3 Protocol` tabs rather than keeping T1/T2 as the active study tabs. Use `replace_existing_goal3_tabs.gs` in the **already existing response spreadsheet**, preview first. It creates date-stamped, hidden **archive copies** of the two old tabs, then deletes their **old active tabs** and creates fresh tabs with the same names for this proposed revised protocol. Old participant evidence/checkbox data, if any, must remain retrievable in the archive; the live `Form_Responses` tab, live Form, and unrelated derived analysis tabs are not touched. The old `create_wildtrack_mvp_evaluation.gs` MUST NOT be rerun (its old tab-creation routines delete the current named tabs).
