# 09 - Archive index

**What to build:** Replace archive record cards with a scalable searchable index and selected-record detail experience. Preserve the distinction between the current demonstration record and the intended independent final-PDF archive without claiming unavailable storage is connected.

**Blocked by:** 02 - Role-specific application shells; 05 - Deliverable-first Review.

**Status:** ready-for-agent

- [ ] Archive records render in a compact searchable and filterable table suitable for multiple terms and hundreds of projects.
- [ ] Filters cover workspace, project, team, student, adviser, deliverable, version, status, and archive date where data exists.
- [ ] Selecting a record opens complete metadata and integrity information without expanding every row.
- [ ] View, download, verify, retry, and relevant bulk actions remain clearly distinct and reflect their real availability.
- [ ] Individual and bulk archive actions use confirmations that state the selected scope and record count.
- [ ] The unavailable Cloudflare R2 or equivalent storage state uses professional factual language and does not claim that a Drive link is an independent archived copy.
- [ ] Long hashes, filenames, project titles, and links do not distort table or detail layouts.
- [ ] Empty, loading, error, verification-failed, retrying, and verified states are complete.
- [ ] Tests cover filtering, selection, action availability, confirmations, integrity states, and class-scale rendering.
